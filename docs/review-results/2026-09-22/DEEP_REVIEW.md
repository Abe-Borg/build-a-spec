Two cross-cutting themes explain most of the list. First, **every "never rolls back" / "one transaction" claim in `CLAUDE.md` was written about the happy path** — the commit block, the export route, the QC apply route and the batch settlement each have a non-`SpecEditError` exception path that was never exercised. Second, **the fakes in `tests/fakes.py` cannot represent the shapes the real SDK produces on failure** — typed `WebFetchBlock`s, mid-stream `error` events, partial `current_message_snapshot`s, `canceled`/`expired` batch rows — so the 1,982 green tests prove the design against a client that never misbehaves.

## 2. Confirmed defects by subsystem

Each entry: what the code does, the concrete failing scenario, how it was verified, and the fix. Line numbers are against `d5c9034`.

### 2.1 Chat loop and conversation engine (`backend/llm/`)

**C-1. Commit block is not transactional** (summary #1). `stream_user_turn`'s success `else:` extends history (3900), commits the document (3903), commits figures/follow-ups/facts, writes QC dispositions, sets `committed = True` (3985) and only then builds `post_commit_events` (`doc.snapshot()`, `open_questions`, `lint_document`, `standards_payload`, 3990–4008). None of it is under a `try`; the `except` chain at 3860–3890 covers only the streaming body. A raise after 3985 skips `finalize_model_turn` and never enters the second `try/finally` (4061–4072): `turn_active` stays True for the session, the SSE stream ends with no `error`/`turn_complete`, and the exception escapes `event_stream()` at `app.py:3553`. A raise between 3900 and 3985 leaves history extended and the document committed (its backup already cleared) while the other three stores roll back — the "resend never duplicates" invariant is broken and a `create_figure` tool_use/result pair survives for a figure that no longer exists. *Reproduced* (both cases). Fix: build the committed message list and the post-commit payload before mutating anything; mutate history last; wrap the block in one `try/except` that yields an `error` event; make the trailing `finalize_model_turn` unconditional in a single `finally`.

**C-2. Thinking-display probe over-catches** (summary #10). `_enter_stream` catches every `anthropic.BadRequestError` and, if `display` is in the request, re-sends without it and sets the process-wide `_display_probe_disabled`. A `prompt is too long` 400 (which C-5 makes inevitable) re-sends the same over-long request and then blanks the thinking strip for the rest of the session; the only record is a trace note. *Reproduced.* Fix: inspect `exc.body`/`exc.message` for the `thinking.display` param path before degrading; log at WARNING.

**C-3. Stop is honoured only at frames `_stream_events` chooses to yield.** The round loop checks `stop_requested` after each yielded UI event (3668–3671); `_stream_events` yields nothing for empty thinking deltas (2840 — every delta once display is `omitted`, which C-2 makes permanent), `input_json_delta` for any client tool except `apply_spec_edits` (2842–2852; a 20 kB `create_figure` SVG, `record_project_facts`, …), signature deltas and server-tool result starts. A Stop pressed during a long thinking phase or a large figure is ignored until the next text/status frame while billed tokens keep arriving. *Confirmed.* Fix: check `stop_requested` per raw event inside the iteration, independent of whether a UI frame is produced.

**C-4. Every `apply_spec_edits` / `apply_qc_fixes` tool result embeds the full compact outline and it is committed forever** (3305, 3384). Measured: a 210-paragraph section renders a 42.8 k-char compact outline ≈ 10.7 k tokens (the "compact" outline is nearly the whole document because provisions are shorter than its 160-char cap). A ten-batch full draft commits ~100 k tokens of stale id-maps that every later turn re-sends (0.1× reads, one 2× write, permanent context consumption, and it pushes the 20-block cache lookback in C-9). The PROJECT CONTEXT already carries the full document each turn. *Reproduced (size).* Fix: elide `outline` from committed tool results (keep `applied`), exactly as `_elide_reference_tool_results` does.

**C-5. No context-overflow handling of any kind.** No reference to `prompt is too long`, compaction, `context_management` or history trimming anywhere in the backend (`MODEL_CONTEXT_WINDOW` feeds only the UI gauge). History grows monotonically (C-4, C-6); once a session crosses the window every turn is a 400 (which trips C-2), the saved `.baspec` reloads the same history, and the only exit is New session. *Confirmed by grep.* Fix: catch the overflow 400 and truncate the oldest exchanges keeping role alternation, or opt into the compaction beta (Sonnet 5 is supported).

**C-6. `web_fetch` text results and `web_search` `encrypted_content` are never elided.** `resend_sanitizer._find_pdf_sources` (51–72) and `elide_all_pdf_sources` touch only `application/pdf`; a fetched HTML page arrives as a text document up to `WEB_FETCH_MAX_CONTENT_TOKENS = 50_000` × `CHAT_MAX_FETCHES = 4` per round, renewed every round. One web-heavy turn can commit ~200 k tokens of page text permanently — the main driver of C-5. *Confirmed.* Fix: elide text fetch payloads at commit (keep url/title), the PDF posture; citations resolve from the surviving text blocks.

**C-7. Mid-stream transport failures are untyped and roll back completed rounds.** During `for event in stream` (2815) an httpx2 read error or the SDK's own `ValueError("Unable to parse tool parameter JSON…")` is not an `APIConnectionError` (that wrapping covers only the initial request), so it lands in the generic `except Exception` (3888) as "Unexpected error" and the whole turn — including doc patches from earlier rounds the user watched land — is rolled back, whereas a user Stop in the same position keeps them. *Confirmed by reading the SDK.*

**C-8. Tool dispatch runs under `_turn_state_lock`** (3835–3849); on a pre-1.14 source-attached project `apply_doc_edits → validate_source_transition` is O(document) per batch and blocks `/api/chat/stop` and every guarded reader for seconds. Low frequency now that imports detach.

**C-9. Cache layout notes** (design, not defects — see section 3): the PROJECT CONTEXT is written to a 5-minute entry at 1.25× every turn and read by no later turn; the 20-block lookback miss the docstring accepts (2410–2418) is fixable for free with the unused fourth breakpoint on the previous boundary.

**C-10. Module docstring drift**: `conversation.py:36` ("All three share one TTL") contradicts the shipped 1h/1h/5m design (`_cache_control`, 2313–2335).

### 2.2 REST layer, locking, desktop security (`backend/app.py`, `sessions.py`, `main.py`)

**R-1. Event-loop stalls** (summary #3). `reference_upload` (4830), `import_master` (5010) and `project_brief_start` (6570) are `async def` and take `session_state_guard()` inline; any thread holding the RLock parks the loop. `template_preview` (3125–3145) takes `active_write` + the guard and then calls `messages.stream(...).get_final_message()` inside it, so for the whole AI-generalize call `/api/doc`, undo/redo/edit, readiness, QC status, usage, the session bundle and `claim_model_turn` all wait, the panel's polls hang, and tutorial transitions are refused. `qc_start`/`qc_apply`/`qc_apply_preview` also run `block=True` sweeps under the guard on a memo miss. *Reproduced* (`/api/health` 4 ms → 29.0 s once an upload was queued behind a parked preview). Fix: never take the guard in an `async def` (commit through `run_in_threadpool`, as `project_load_file` already does at 6716); restructure `template_preview` as capture-under-guard → model call → re-check `doc.index`/generation under guard (the export/chat pattern already in the file).

**R-2. Markdown image exfiltration** (summary #4). Fix: `disallowedElements={["img"]}` (or a `components.img` placeholder) on both renderers **and** drop `https:` from `img-src`; add `frame-src 'self'`. Related: `script-src 'unsafe-inline'` / `style-src 'unsafe-inline'` are looser than the Vite build needs.

**R-3. Reference upload requires a live Anthropic call and a missing key surfaces as a 502.** `get_client()` is evaluated inside the `try` at 4808–4818 whose `except Exception` returns 502 "Could not count the document with Anthropic's token counter: <MissingApiKeyError text>". Every attached file's full text is also posted to the API at upload time, which no trust surface says. Fix: catch `MissingApiKeyError` → 400; consider a local estimate for the cap and count remotely only when a key exists.

**R-4. The update installer can spawn mid-import / mid-upload / mid-QC-apply.** `_install_gate_refusal` (7048–7075) uses `sessions.busy_reasons` (turn, research, audit, QC only); the `_active_writes` lease held by `_lease_slow_session_operations` is never consulted and the install-hold middleware only blocks *new* mutations. Click Install while a 25 MB master parses on a worker → gate passes → download → re-check passes → `os.startfile` → the app closes with the import uncommitted. *Confirmed by reading `_busy_reasons` (sessions.py:172–188).* Fix: refuse when `_active_writes > 0` in both gate readings.

**R-5. `reset` (3014) and legacy `project_load` (6627) bypass the lease and busy gates** — the only two mutating routes outside the lease contract; a reset racing `begin_tutorial`'s clone (which runs outside the manager lock) is ordering-dependent.

**R-6. The lease middleware can 409 a request whose side effects already committed.** `active_write.__exit__` (sessions.py:175–190) runs `assert_active` after the handler finished, so a workspace change would replace a successful "research started"/"QC applied" response with `stale_workspace`. Unreachable today only because every transition refuses while `_active_writes > 0` (except `force_restore_original(abandon_transition=True)`), an invariant with no pin.

**R-7. Trace recorder lazily started under the turn-state lock** (`app.py` ~5375 → `ResearchRunner.start` → `_trace.research_start` first-call mkdir + `run.json` write) — the hazard class the file's own `app_event` rule forbids. One-time.

**R-8. Negative or huge `position` on `add_article`/`add_paragraph` is silently clamped** (`model.py:725–731`) rather than refused; `move` validates its range. A nit, but the tool loop exists to self-correct on errors, and a clamp hides a model mistake.

**Security posture (sound, with residuals).** The loopback boundary is well built: exclusive ephemeral socket, nonce-in-fragment → header token + HttpOnly/Strict cookie with a nonce-derived name, Host (421) and Origin (403) allowlists ahead of CORS, `compare_digest` with the non-ASCII guard, cookie-only mutations needing an allowed Origin, rejections taking no lease. Upload and OOXML hardening is good (byte ceilings, ZIP member/uncompressed caps, traversal/symlink/encrypted member rejection, `resolve_entities=False` on every lxml parser, streaming size checks on `.baspec`, RecursionError caught on JSON, CSV formula leaders neutralised). Residuals worth a decision: the updater has no code signature (manifest and installer share one https channel; SHA-256 from the manifest is the only integrity gate; verify → `os.replace` → `os.startfile` is a same-user TOCTOU); the plaintext API-key file is `0600` on POSIX only and a key file next to the executable is honoured; redaction covers `sk-ant-`/`sk-`/Bearer/AKIA shapes only; `/api/health` hits the OS keyring on every poll.

### 2.3 Research (`backend/research/`)

**S-1. Mid-stream provider errors are unretried** (summary #2). *Reproduced:* mid-stream `overloaded_error`/`api_error`/`rate_limit_error` → `APIStatusError(status_code=200)` → `unknown` → not retried; the same error before the stream opens (HTTP 529) → `server_error` → retried. Also `ReadTimeout('')` → unknown (substring heuristic on an empty message), the SDK accumulator's `ValueError` → unknown, and 408/409 → `invalid_request`. Fix: in the `APIStatusError` branch consult `exc.type` (`overloaded_error`/`api_error` → SERVER_ERROR, `rate_limit_error` → RATE_LIMIT) before status codes.

**S-2. Failed fetches ground citations; typed fetch results drop the final URL** (summary #8). `collect_fetch_evidence_detailed` appends `server_tool_use(web_fetch).input.url` unconditionally (303–310) and only counts a paired `web_fetch_tool_result_error`; the success branch reads `document.url` only when the block is a `dict` (311–330), but the SDK delivers a `WebFetchBlock` object. *Reproduced end to end* (`grounded: True`, `accepted_sources: ['https://hallucinated…']`). Fix: pair each fetch use with its result by `tool_use_id`, collect the URL only from a successful result, read `url` via attribute access regardless of type.

**S-3. Readiness is revoked by a stopped or failed later round.** `_research_readiness` (`app.py:1620–1621`) gates on `status != "complete"` while `stop()` and a failed round set `failed` with the profile and coverage intact. *Reproduced over the API.* Fix: derive readiness from `research_coverage` whenever a profile exists; use the runner status only for never-researched / running.

**S-4. A new round can start while a stopped round's streams are still running, and Stop never stops billing.** `start()` refuses only on `status == RUNNING`; the research route never checks `is_settling` (QC's does); `_relay_stream_activity` never breaks and `should_stop` is polled only between calls, so each stopped worker streams to completion, spends its full search budget and is metered through the success sink; the retry `time.sleep(backoff)` is likewise uninterruptible. *Reproduced* (`start` → 200 while old workers were blocked; eight streams). Fix: 409 while settling, and check `should_stop()` inside the relay with `stream.close()`.

**S-5. `normalize_url` rejects common equivalent forms** (61–104): leading `www.`, percent-escape case, unreserved escapes, doubled slashes, space vs `%20` — seven rejects on semantically identical pairs, all on the conservative side, so real citations read `[UNVERIFIED]`.

**S-6. The `<already_established>` frame is neither neutralised nor declared as data** (1290–1305, 1203–1206) — requirement text from model paraphrase of hostile pages or a shared `.baspec` reaches the next round's brief verbatim; a `</already_established>` inside it closes the frame. Same hole class the reference-document work closed.

**S-7. `_confirm_item` lets an ungrounded re-assertion raise a grounded item's confidence** (`confidence=max(prior, fresh)` at 1017–1055 regardless of `fresh.grounded`, while `research_date` correctly ignores it). Round 2 restating an item at 0.95 with no source → 95 %, grounded, dated round 1; the context block trims lowest-confidence-first, so this inflates what survives.

**S-8. Water-filling drops the pool remainder and truncates a document that would fit** (`reference_docs.py:597–630`; budget 10, sizes 3/4/20 → `{3,3,3}`), adding a "PARTIAL" marker to a document that fit. Small.

**S-9. Raw exception reprs reach the drawer** (2110–2114): S-1's failure renders as a Python dict.

**S-10. `GET /api/research/stream` on an idle runner blocks a threadpool worker for 1,800 s** (idle is not terminal; `runner.py:664–716`). Reachable only by a direct GET.

### 2.4 Final QC engine (`backend/qc/engine.py`, phases and transports)

**Q-1. Timeout-cancelled seats are recorded "Cancelled by user."** `settle_open_batch(status="timeout")` (5606–5613) → `_consume_batch_results(recovering=True)` → `_apply_batch_item` settles every `canceled` row with the user-stop message (5786–5788), which `_verifier_outcome` maps to `status="cancelled"`. The audit record and Review Room say the user stopped seats the provider never started, while the terminal `verification_batch` event says `timeout`. *Reproduced.* Fix: thread the settlement reason into `_apply_batch_item`; settle timeout cancellations with the ceiling message and `FailureClass.CONNECTION`.

**Q-2. Evidence gate accepts self-references** (summary #5). *Reproduced* for `sec`, `pt1` and the finding's own anchor. Fix: exclude `sec`, parts, the finding's element and its ancestors from `document_ref` evidence (the refutation ground is "handled *elsewhere*"); optionally require a quoted excerpt verified against the referenced element's text; reword the schema example.

**Q-3. Verifier seats see neither `<standards_in_effect>` nor the research profile** (summary #7). *Confirmed by reading `_verifier_shared_prefix(section_render, today, reference_documents, project_facts)`.* Fix: add `_render_standards(module, section)` to the verifier prefix (hundreds of cached tokens) and at least the profile items the finding references.

**Q-4. The batch discount is applied to the per-search web fee.** `_verifier_outcome` passes `cost_multiplier=0.5` into `estimate_usage_cost` (`usage_ledger.py:161–199`) and `_estimated_cost_from_basis` (526–560); both multiply `web_search_requests × WEB_SEARCH_COST` by it, while Anthropic prices web search inside Batches at the normal rate. Every batched web-tool seat under-reports by $0.005/search; the run total and the session meter's `qc_batched` bucket inherit it. *Confirmed by reading.* **Coupling hazard:** both formulas share the error, so `_audit_accounting_consistent` reconciles today; correcting either alone leaves a $0.03 delta on a six-search seat (`abs_tol 1e-9`) → `from_dict` returns `None` → every persisted batched report with searches is silently discarded on load. Fix both together and version the rule.

**Q-5. `_batch_error_facts` claims an unknown error type "degrades to a retryable-unknown"; `UNKNOWN` is not retryable** (5083–5091 vs `retry_policy.py:37–44`). An `errored` row with a new error type settles the seat failed at attempt 0. Errored batch rows are unbilled, so retrying `UNKNOWN` in the batch path is free.

**Q-6. `api_request_count` differs between transports for the same history** (batch counts only `succeeded` rows, 5820; streaming counts every request, 3608) — the "byte-identical audit records" claim holds only for a seat that never errs.

**Q-7. The streamed retry backoff ignores Stop** (bare `time.sleep(backoff)` at 3730, up to 20 s) — the batch path got `_sleep_interruptibly`, phase 1 and the non-batch phase 2 did not.

**Q-8. The main batch poll is unbounded**: `batches.retrieve` (5574) runs on the module client (SDK `max_retries=2`, 600 s read timeout) with `should_stop()` consulted only between polls; one black-holed poll holds Stop for ~30 min. The settlement window uses `_bounded_client` for exactly this reason; the normal loop should too.

**Q-9. A user Stop during phase 1 is recorded `failed`, not `cancelled`** (`_run_lens:4045–4054` writes `status="failed", error="Cancelled by user."` although `cancelled` exists) — every report surface reads a Stop as a failure.

**Checked and not defects:** SDK serialisation of pydantic blocks inside batch continuation params; a stopped-but-recovered batch cannot read `complete`; `web_search_tool_result` error objects do not crash grounding; TTLs uniform per request with ≤ 4 breakpoints; streamed and batched seats build byte-identical params via `_qc_request_kwargs`; `should_stop` threading at every attempt/continuation boundary; `custom_id` uniqueness per round.

### 2.5 Final QC record, persistence, apply, readiness (`qc/engine.py` dataclasses, `qc/runner.py`, `qc/apply.py`, `op_conflicts.py`, `context.py`)

**P-1. Multi-op safe fixes are unapplyable** (summary #6). *Reproduced:* two `add_paragraph` to one article, two `delete`s in one article, `delete`+`add_paragraph`, `replace`+`set_status` on one paragraph — all `ops_valid=True`, all `planner_conflicts=1`. The UI, the context block and the debrief still call them "verified safe fix". Fix: never conflict a finding with itself (its op order is fixed by construction); plan write-sets per finding and compare across findings only.

**P-2. Discarding a paid report on load is completely silent.** `spec_doc/project.py:510–513`: `QCResult.from_dict` → `None` → no log line; readiness reads "Final QC has not been run", dismissals and applied dispositions are gone. Validators that return `None` for a legitimately produced record on the next release: the lens roster gate (2567–2575 — adding or renaming any lens discards every retained report), `_persisted_cost_basis` shape pairing (435), the accounting rule (Q-4), `_manifest_claims_consistent` field drift (2062), a protocol bump (2549). Fix: log a WARNING naming the failing gate; better, keep the record as non-actionable latest-attempt evidence (the `restore()` slot exists) instead of `None`.

**P-3. Fix-survival evidence voids an applied fix on a status-only edit and records a false statement.** `_element_own_state` (`apply.py:482`) includes `status` and `source_item_id`; apply a `replace` then `set_status confirmed` on the same paragraph in the same turn → `fix_survives` False → the finding stays open with an `apply_stale` event saying "the committed document does not contain the verified remedy" while the remedy text is present. ## 3. Claude API usage: misuse, missed features, caching and cost

**What is right, and should stay.** Model ids and prices match the current list (Sonnet 5 $2/$10, Opus 5 $5/$25, cache read 0.1×, cache write 1.25×/2.0×, web search $0.01). Every channel states `thinking: {type: "adaptive"}` plus `output_config.effort`; no `budget_tokens`, no assistant prefill, no sampling parameters. Web tools are the `_20260209` variants with `allowed_callers: ["direct"]`. Every fan-out output tool is `strict: true` with `additionalProperties: false`. `stop_reason == "refusal"` is handled on every channel with `stop_details` read defensively. The chat request's three breakpoints are non-increasing in TTL (1h → 1h → 5m), and the rolling committed-history boundary genuinely produces a cache read on the next turn. The SDK client is built with an explicit `anthropic.Timeout(600, connect=5)` and `max_retries=2`. The typed-exception order in the chat loop (Authentication → APIStatus → APIConnection) is right.

**What is wrong or missing.**

1. **The retry classifier cannot see mid-stream errors** (S-1). The one failure a long web-search stream actually produces is unretried on every fan-out. Consult `exc.type` before status codes.
2. **`eager_input_streaming` is off on every client tool.** The API therefore buffers each `apply_spec_edits` batch and emits its `input_json_delta` frames in a burst after generation, so the app's own "drafting… N chars" meter is dead UI for the 30–60 s a 25-op batch takes, and Stop cannot land during it (C-3). The consumer side is already safe (`_safe_json`, the truncation branch, `apply_edits` validation), so this is one key on two tool definitions plus a guard for the SDK's parse `ValueError`. One-time cache invalidation of the chat lineage.
3. **No `additionalProperties: false`, no `strict`, no `input_examples` on any of the seven chat tools.** `apply_spec_edits` has `required: ["action", "target_id"]` over 17 optional fields: `set_status` without `status` and a misspelled `source_item_id` are schema-valid and fail or are silently ignored at runtime, each costing a full extra round (the whole prompt re-read plus a tool result). A per-`action` `anyOf` under `strict: true` is recursion-free and supported.
4. **The schema advertises `status: "imported"` and `apply_edits` accepts it** (*reproduced*): the model can stamp its own provision as imported, which lands it in the export's "IMPORTED PROVISIONS NOT YET REVIEWED" schedule and hides it from the assumptions audit — while the description and the prompt both say it never does.
5. **The research fan-out has four cache lineages, not one.** `max_uses` differs per dimension (40/12, 32/10, 24/8, 16/8), so the `tools` array — which leads the prefix — differs; block 0 (references + facts, up to ~30k tokens) is written four times and read by nobody, and all four requests fire concurrently anyway. Unify `max_uses` and stagger the first request by its first streamed token. Also: **no breakpoint on the re-sent assistant content**, so every `pause_turn` continuation re-bills the growing conversation (~$5–8 per round across four dimensions, modelled).
6. **Batched verifier seats write a 1h entry each, and batch cache hits are only best-effort.** Under Batches a 1h write costs 2.0 × 0.5 = 1.0× of standard input — *more* than sending the same bytes uncached in the batch (0.5×); the write pays only if ≥3 seats per lineage hit. The per-seat `cache_creation_1h_input_tokens`/`cache_read_input_tokens` are already recorded in every report — read one real export before changing anything; if hits are poor, drop to 5m or unmark, or pre-warm the lineage with one streamed seat.
7. **Phase-1 breakpoints on the four non-web lenses are pure premium**: one request each, all concurrent, so four 1.25× writes and zero reads (~$0.12/run); consolidation buckets likewise. Stagger one lens ahead by its first token, or drop the markers on no-continuation requests.
8. **The chat cache layout re-writes session-stable content every turn.** The research profile (5–15k tokens typically, capped at 100k), standards, facts, QC block and stubs ride the tail, written at 1.25× per turn and never read by a later turn. A **second top-level `system` block with its own 1h marker** (the unused fourth breakpoint) would bill them at 0.1× between changes; the document and the date/time stay in the tail. Sonnet 5 has no mid-conversation `role: "system"`, so this is the only cache-preserving placement. Separately, the 20-block lookback miss the docstring calls "rare" is the norm for full-draft and adapt turns (7+ edit rounds ≈ 21+ positions); an intermediate breakpoint ~15 positions before the boundary closes it.
9. **Committed history is not bounded** (C-4, C-5, C-6). Elide outlines and fetched page text at commit; handle the overflow 400; consider the compaction beta.
10. **`fallbacks` is unused.** A classifier refusal on a phase-1 lens (clean-agent or hazmat chemistry is plausible in Division 21) makes the run partial; phase 1 streams and could carry `betas=["server-side-fallback-2026-07-01"], fallbacks="default"`. Batches reject `fallbacks`, so phase 2 cannot.
11. **`count_tokens` is used for reference documents only.** One call per QC run would record real prefix sizes in the manifest and guard the batch submission; and the reference upload should not require it at all (R-3).
12. **The AI-generalize template call re-emits the whole document as tool input** (up to 128k output tokens at $10/M on a 1.5 MB cap, minutes, and a strict structure contract that rejects any drift). Emitting `replace` ops for the paragraphs that need generalising would be an order of magnitude cheaper and preserve structure by construction.
13. **Forward-compatibility note.** Strip-at-commit (PROJECT CONTEXT replaced, thinking dropped, PDFs and reference results elided) rewrites earlier turns. That is allowed on Sonnet 5 / Opus 5 today, but it is exactly the history editing that preserved-thinking models (Fable 5.1 now; "later models enforce it for everyone") reject or degrade — a future chat-model migration will need turn-scoped system messages or retained reminder blocks instead of the strip.

**Effort.** Interview, research and lens effort are all `high` (the API default), verifier `medium`. Chat routes are the workload Anthropic's guidance says most often does well at `low`/`medium`; `high` on every interview turn is the single largest discretionary spend knob in the app and has never been measured — there is no eval (section 6). Do not change it blind; build a 20–30-session eval from frozen sessions and the readiness/lint/QC telemetry the app already records, then sweep.

## 4. Prompt findings

The prompts are in good shape on the patterns that matter most: no scratchpad tags, no JSON-in-prose forcing, no prefill, one-line personas, no grader vocabulary, the untrusted-attachment defence is correct on every channel that has it. What follows is what the audit found beyond that, in impact order.

1. **Both Final QC stages carry a conservative filter that Opus 5 follows literally.** The lens prompt says "Report only real, actionable defects a senior reviewer would want fixed before issue" (`qc/engine.py:2921–2922`); the verifier prompt says "Default to refuted when uncertain — only real, actionable defects survive this pass" (`:3136–3139`). Anthropic's Opus 5 migration guidance documents that "only report…"/"be conservative" instructions depress measured recall while the bug-finding ability is intact, and prescribes a separate verification step — which this app already has (consolidation + panel). Commit `c912aa8` (Sep 14) replaced the lens sentence with coverage-first; `90918c7` (Sep 15) restored it on a cost argument (every candidate buys a panel). The cost concern is real but is a volume control that belongs in code (a per-run candidate cap, or `low`-severity advisory candidates skipping the panel), not in a recall-suppressing sentence. On the verifier, "default to refuted" now interacts with the v4 evidence gate: for critical/high it manufactures `disputed` outcomes (unsupported refute → disputed → readiness blocked, human rationale required); for medium/low it silently kills uncertain findings, and with Q-2 the seat can cite the paragraph itself to make the kill "validated".
2. **The QC lenses are handed the chat tool's contract** (`_op_vocabulary()` returns `APPLY_SPEC_EDITS_TOOL["description"]`, ~4k chars in every lens lineage). It presents `set_project_identity`/`set_project_profile` as available ops that `_clean_op` then drops **silently**, and its "Mark undecided values inline as [TBD: …]" instruction is exactly what the verifier is told to reject (`ops_adequate=false` for ops that introduce `[TBD]`). Replace with a QC-specific block listing `QC_OP_ACTIONS` and the completeness rule.
3. **The `suggest_prompts` description forbids the chips the debriefs require** (`suggestions.py:132–135`: "research runs, Final QC, export, undo, and saving are panel buttons, not chat messages" vs the stable policy's carve-out and the debrief directives asking for "Yes — apply the verified safe fixes" chips). The tool description is the stronger signal at call time.
4. **Verifier seats receive the lens brief's imperatives** ("USE web_search to check the standard's ACTUAL current content") framed as their own instructions; most seats have no web tools and the ones that do spend their allowance on every compliance finding. Reframe as context. **Non-web lenses are told to "cite URLs retrieved this turn."** **The verifier output section never mentions `refutation_evidence`**; only the schema field explains that a critical/high refutation without evidence is escalated — and after Q-2 it must also say what does *not* count.
5. **Contradictions in the stable chat prompt**: four batching rules ("one batched call where possible", "batch related edits", "~25 ops, a guide not a cap", "ONE operation per call when unsure"); "at most 3 questions per turn" vs "surface exactly ONE waiting item… never raise a second"; "record it with `set_standard_edition` — then draft to it" vs the research debrief's "PROPOSE ONLY"; "say in one line what you assumed" vs a full-draft pass that stamps dozens of assumptions. Each is one sentence to reconcile.
6. **Stale weight in the cached prompt.** The IMPORTED DOCX EDITING BOUNDARY guidance appears in `_HOW_YOU_WORK`, `_TOOL_GUIDE`, three `_GAP_AND_ADAPT` bullets and the adapt directive (~1.7k chars plus ~1.1k of surrounding rules), but every import has detached since v1.14.0, so the dynamic boundary block — which already carries the rules — renders only for pre-1.14 projects. ~12k of the 34.5k-char stable prompt restates tool contracts (`_FIGURE_POLICY`↔`create_figure`, `_PROJECT_FACTS_POLICY`↔`record_project_facts`, …); cheap at 0.1×, but the disagreements above live in those copies. Put HOW in the tool description and WHEN in the policy.
7. **Per-turn choreography** ("Each turn: 1. Absorb… 2. Call apply_spec_edits… 3. …ask at most 3") reads as "edit every turn" to a model that reaches for tools readily; a judgment-shaped instruction ("when the message settles something, fold it in; when it is a question, answer it — an edit is not owed every turn") fits Sonnet 5 better.
8. **Research protocol contradiction**: "must be supported by sources you actually retrieved" vs "report it with confidence 0 and explain in notes" — as written the "must" clause is dead and ungrounded items enter the profile at 0 %. Also "prefer retrieving the primary instrument itself" plus 12 fetches × 50k tokens invites fetching whole codes (the main research cost driver alongside the missing continuation breakpoint), and the established-facts directive asks the worker to re-verify `[UNVERIFIED]` items without giving it the URLs the earlier round already named.
9. **Four JSON-in-prose escape hatches remain** ("If you cannot call the tool, emit the same payload as JSON wrapped in `<…_json>` tags") plus their regex parsers; with `strict: true` tools under `tool_choice: auto` the sentence only advertises a text path. Remove the sentence, keep the parser as a silent net.
10. **Factual drift in code comments that describe the API**: "all three share one TTL" (they do not — 1h/1h/5m, and only longer-before-shorter is constrained); "block 0 is identical across every verifier seat" (two lineages); research's "written to cache once and read thereafter" (per dimension only); the reference-doc tool's "inexpensive to request" (a re-read bills the whole document).

## 5. Architecture-level observations and alternatives

Each of these is a design decision rather than a bug; the trade-off is stated so the owner can decide.

1. **Make every commit a transaction with a single `finally`.** The chat commit block (C-1), `qc_apply` (no `finally` around `begin_turn`), the preserving export (`ValueError`/`RawZipError` escaping as 500s) and the batch settlement all share the shape "happy path is one block; the first unexpected exception leaves the session in a state no code path handles." A `RequestSnapshot` helper (lease, session, generation, doc index/record, detached tree, `.still_current()`) already exists in three hand-rolled copies (export, chat request, project package) and would also make `template_preview`'s AI call trivially lock-free.
2. **One rule for locks in async code, enforced by a test.** Forbid `session_state_guard()` inside `async def`; commit through `run_in_threadpool` as `project_load_file` does; add the "park the guard on a thread, assert `/api/health` still answers" test shape for every `async def` route. Every existing responsiveness test blocks the CPU half, never the lock.
3. **Bound the conversation.** Elide at commit everything a store already holds (outlines, fetched page text) exactly as PDFs, figure sources and reference bodies are elided; then either deterministic truncation of the oldest exchanges when `last_context_tokens` approaches the window, or the compaction beta. Trade-off: truncation loses early chat; compaction adds a beta dependency. Without one of them a long session has a hard failure with no recovery.
4. **Split "session-stable" from "per-turn" context** (a second system block, section 3 item 8). Trade-off: one extra 2× write whenever research, facts or references change.
5. **Give verifier seats what they need to adjudicate** (standards block + referenced profile items) and **tighten the evidence gate** (exclude self and ancestors; require fetched rather than merely search-listed sources). Trade-off: a few more `disputed` escalations, for a gate that means something.
6. **Move Final QC's volume control into code.** Replace the recall-suppressing prompt sentences with a deterministic policy: `low`-severity ops-less (advisory) candidates skip the panel (a human triages them anyway; they can never be auto-applied), or a per-run candidate cap; decide with the candidate/outcome/cost telemetry every `QCResult` already carries. Sonnet 5 seats for medium/low stay a deferred item for the same telemetry.
7. **Degrade, never discard, on QC reload.** Two tiers: parse-level failures → `None`; integrity failures (accounting, partition, outcome relabel, roster, cost-basis shape) → load with an `integrity_issues` list, non-actionable, rendered in readiness and the report. The non-actionable slot already exists. Separately, **hash review inputs and record provenance** (app version, prompt text, rule prose) so a release or a prompt edit does not force a paid re-run; and **plan conflicts per finding write-set** so multi-op safe fixes apply.
8. **Separate claim identity from adjudication in the finding id** so dismiss memory carries when the claim and outcome class match rather than only when a 2–3-seat LLM panel votes identically twice.
9. **Research: stop should close the streams** (`should_stop()` inside the relay + `stream.close()`), readiness should derive from coverage, a tail breakpoint should cover continuations, and grounding could use the `citations` the fetch tool is already asked for (a citation with a quoted span proves the claim; retrieval only proves the page loaded — and it would resolve S-2 for free). The merge should let a correction name what it supersedes (ids in the established-facts block, a `supersedes` field).
10. **Lint scheduling.** Compute `duplicate_provision` only in the SSE lint event after a doc-changing turn, memoised on the document hash, with `real_quick_ratio()`/`quick_ratio()` gates, length-band buckets and a per-list pair cap — never in `_doc_payload` or readiness.
11. **Importer/exporter.** Keep locked blocks as siblings at the current depth (or render unmodelled and locked content by origin index); record the element kind and label separator in `FormatAnchor` so new headings and first-of-depth provisions clone the right kin; unify label positioning on one function; promote `N.M` lines only when they form a monotone sequence with the current part and warn on every promotion of an unlabelled line; preserve inline structure on edit by run-diffing (bookmarks, hyperlinks, footnote refs survive).
12. **Frontend.** A reducer with `RESET_SESSION`/`LOAD_PROJECT` actions rebuilding the whole record (mirrors the backend field-sweep test); one `Follower` abstraction for research and QC (backoff, cap, abort, generation, epoch); a request-rank latch on every document-payload writer; move the transcript out of `App` (or `memo(ArtifactPanel)` with stabilised callbacks) so a streamed token does not reconcile the whole document; a markdown renderer policy object (custom `a`/`img`, strict URL transform) as the one place the trust dossier's network claim is enforced; a typed event union generated from, or asserted against, the emitting backend code (the capability-contract pattern); `React.lazy` for the five large modals (the 967 kB main chunk).
13. **Generic store base and one attachment type.** The four turn-atomic stores diverge exactly where each was hand-written (dedupe on load, bool-safe `next_seq`, field caps); references, figures, brief records and tutorial fixtures are one `(id, kind, title, body, token_count)` shape with `render_for(channel)` owning the escaping, so T-2 cannot recur across three renderers.
14. **Split `app.py` into routers** sharing a `deps.py`, declaring the lease-guarded and install-hold-exempt route sets on the routers (a dependency) rather than as hand-maintained string sets, so a new mutating route cannot silently miss either.
15. **Hermetic tests, hermetic fakes.** Force-set the env in `conftest`, redirect trace/log/update-state to tmp; give `_FakeStreamCtx` a real accumulate-so-far snapshot, a `raise_after(n)` iterator, `message_delta` usage frames and typed 429/5xx/timeout errors; give `_FakeBatches` an async mode that yields `in_progress → ended`, out-of-order and duplicate rows, `expired`/`canceled` results by default; add a light happy-dom + testing-library harness under `node --test` for ReviewDrawer, the SpecDocument edit paths and QCDrawer, where the highest-risk state machines are untested end to end.

## 6. Test suite: what the 1,982 green tests cannot see

- **Only the happy path of every "transaction" is exercised.** Nothing raises inside the chat commit block, the QC apply route after `begin_turn`, or the preserving export after the readiness check.
- **The fakes never misbehave the way the SDK does.** `_FakeStreamCtx.current_message_snapshot` returns the full scripted content (no partial tool input, no signature-less thinking block, no partial `server_tool_use`); `__iter__` never raises mid-stream and no test constructs the SDK's mid-stream `APIStatusError(status_code=200)`; fetch results are dicts, never `WebFetchBlock`s; `_FakeBatches` is synchronous, always `ended`, in submission order, never `expired`/`canceled`, and `cancel` changes nothing; `with_options` returns `self`, so settlement bounds are asserted by recorded kwargs, never enforced; no test sends two `tool_use` blocks in one message; no stop lands during a silent stretch (every stop test sets the flag from a yielded `text_delta`).
- **Persistence is untested on ten surfaces** because the shared fixture cannot reload (P-4); no test observes a `from_dict` discard on load, a lens-roster change keeping old reports loadable, or the two cost formulas moving together.
- **Contract tests that cannot fail or fail for the wrong reason**: `test_qc.py:437–457` cements the own-anchor evidence hole; `test_a_refuting_seat_that_cites_what_it_retrieved_refutes_cleanly` proves that a search-listed (never fetched) URL counts as evidence; the "immediate restart works" research test pins S-4; source-text pins satisfied by a YAML comment; the frontend's regex-over-source pins (`strandedState`, `dialogs`, `chatPerf`, `sessionBundle`) enforce spelling rather than behaviour.
- **No performance guard** on `lint_document` for a flat article, on `/api/qc/status` with a production-shaped report, or on the document panel per streamed token.
- **No DOM harness** for the frontend's riskiest state machines; no framing tests for `readSse`; no test of the reconnect cadence; no field-sweep test for `clearSessionState`; nothing scans class names against `@theme` tokens; nothing pins the markdown element/URL policy or that every `href` from persisted data goes through `safeHttpUrl`.
- **`conftest` hermeticity is `setdefault`** (X-1): a developer's exported `ANTHROPIC_API_KEY` or `BUILD_A_SPEC_TRACE=1` silently changes what the suite does.
